SYSTEM WORKFLOW

How Our ERP System Works

Complete offline-first ERP workflow designed for fast local operations, automatic cloud synchronization, and enterprise-grade reliability.

1

User Login & License Validation

ERP validates user permissions, device authorization, and active subscription license before allowing access.

2

Billing Counter Operations

Billing counters send invoices directly to the local ERP server over LAN/WiFi for instant processing and printing.

3

Inventory & Warehouse Updates

Stock changes are updated in real-time across all counters and warehouse systems through the local server.

4

Counter-Wise Cash Management

Each counter maintains separate cash tracking with end-of-day closing and manager approval workflows.

5

Offline Business Continuity

Even without internet, billing, inventory, accounting, and printing continue normally.

6

Automatic Cloud Synchronization

Once internet becomes available, the local ERP server securely syncs sales, reports, inventory, and backups to cloud.

7

Web Dashboard Monitoring

Owners and resellers can monitor branches, sales, inventory, and reports remotely from anywhere.

8

Backup & Recovery Protection

Automatic local and cloud backups ensure complete business continuity and disaster recovery.

DATABASE SCHEMA

Core ERP Database Structure

party — Unified Customer + Supplier entity. A party can be both simultaneously.
Column Type Constraints & Notes
id BIGSERIAL PK Primary key
uuid UUID UNIQUE External-facing ID (prevents enumeration)
party_code VARCHAR(50) UNIQUE Auto-generated: PTY-0001
name VARCHAR(500) NOT NULL English name
name_ar VARCHAR(500) Arabic name for Saudi compliance
vat_number VARCHAR(20) UNIQUE 15-digit Saudi VAT
is_customer BOOLEAN NOT NULL Can sell to
is_supplier BOOLEAN NOT NULL Can buy from
status VARCHAR(20) active | inactive | blocked
created_by BIGINT FK → app_user(id)
created_at TIMESTAMPTZ Audit trail
customer_data — Extension of party with customer-specific fields (credit_limit, credit_days, outstanding, etc.)
sales_invoice — Core billing document. Status: draft → posted → printed
Column Type Constraints & Notes
id BIGSERIAL PK
invoice_number VARCHAR(30) UNIQUE INV-2026-0001
branch_id BIGINT FK → branch(id)
customer_id BIGINT FK → party(id)
invoice_date DATE Document date
sub_total NUMERIC(18,4) STORED Before tax/discount
vat_amount NUMERIC(18,4) 15% Saudi standard VAT
grand_total NUMERIC(18,4) STORED sub_total + vat
status VARCHAR(20) draft | posted | printed
sales_invoice_line — Line items with qty, rate, discounts, tax per line
item — Core inventory master with tracking (batch/serial), VAT, pricing
Column Type Constraints & Notes
id BIGSERIAL PK
item_code VARCHAR(50) UNIQUE SKU
barcode VARCHAR(100) UNIQUE EAN/UPC
category_id BIGINT FK → item_category(id)
cost_price NUMERIC(18,4) LPR — Last Purchase Rate
selling_price NUMERIC(18,4) LSR — Last Selling Rate
tracking_type VARCHAR(20) none | batch | serial
is_service BOOLEAN Service items have no stock movement
inventory_transaction — Insert-only ledger for stock tracking. Current stock = SUM(qty) per item+warehouse
purchase_invoice — Supplier billing with GRN linkage
Column Type Constraints & Notes
id BIGSERIAL PK
po_number VARCHAR(30) PO-2026-0001
supplier_id BIGINT FK → party(id)
grn_id BIGINT FK → grn(id) Goods Received Note
po_date DATE Document date
sub_total NUMERIC(18,4) Before VAT
vat_amount NUMERIC(18,4) 5% or 15% VAT per line
Masters — Reference data for system configuration
Table Purpose Key Columns
area Geographic zones code, name, region, status
route Sales routes per area area_id, code, name, status
brand Product brands code, name, status
unit_of_measure UOM (kg, box, pcs, etc.) symbol, conversion_factor
credit_term Payment terms (Net30, Net60) days, credit_limit
payment_method Payment types method_type (cash, bank, card)
tax VAT rates rate (15%, 5%, 0%)
